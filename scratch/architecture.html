Key Operational Insights

The architecture operates on a unified internal bridge network (`umami_default` and `default`). The only port exposed to the host machine is `8080`, managed by the Nginx caching layer. This protects the Next.js server from direct connections and offloads heavy map tile fetching.

The intelligence resolving system (`oasis-vision-intel`) does not talk directly to the client browser. Instead, Next.js calls it internally via `http://oasis-vision-intel:4000/resolve` when the user clicks on entities like aircraft or vessels, keeping API keys and data flows secure within the server environment.

Data caching strategies are separated by domain: Web tiles are cached on disk via Nginx, massive static feeds (like satellites) are cached on disk by Next.js, and entity resolution data is cached in-memory (LRU) inside the intel container.
